## 使い方
普段はChatGPTに**日付・競艇場・R番号が分かるスクショを送ればよい**。会場・日付・Rをこちらが確認して `boat-ai/runtime/request.json` をGitHubへ更新すると、Actionsが起動し、公開データから必要な情報を再取得する。画像をGitHub ActionsがOCRする仕組みではなく、**ChatGPTがレースを特定してトリガーを更新する方式**。

ChatGPTを介さずiPhoneで起動する場合は、[Actionsの画面](https://github.com/hmk2zhgrkt-png/asobi-no-tane/actions/workflows/boat-ai-live.yml) で **Run workflow** を選び `date / venue / race` を入力する。競艇場コードは01～24（02=戸田、18=徳山）。

## 入力と出力
- 2023-11～2026-10末までの公式成績から独自に集計した選手別・モーター別履歴を `boat-ai/runtime/data/*snapshot.gz.b64` に保存。
- [BoatraceCSV（MIT License）](https://boatracecsv.github.io/) の公開CSVから、11月1日以降の確定結果/過去展示、当日の出走表/現行モーター更新日/開催節の過去走/展示/気象/締切前3連単120通りのオッズを取得する。取得禁止を告げられた「ボートとデータ」にはアクセスしない。
- `latest_results/report.json` : 実行状態、取得日時、締切、入力欠損、モーター更新日検証
- `latest_results/features6.csv` : 6艇×28特徴量
- `latest_results/predictions120.csv` : 3連単120通りの推定確率、当時オッズ、推定EV
- `latest_results/paper_candidates.csv` : 条件を満たしたときのみ最大3点
- `paper_ledger.csv` : 仮想購入と結果精算の履歴

## 制限・保守
- **実際の投票は一切行わない**。仮想購入は最大1日2レース・1日1000円・1R3点・推定EV120%以上。ユーザーの実購入とは別。
- 最終オッズは締切直前に変化する。使用している `od3` は数分前の「集計中オッズ」。結果判明後の払戻金は別途公式発表値を照合する。
- 最新データが欠損・時間不明なら `DATA_NOT_READY_SKIP`、締切後なら `REPLAY_OR_UNVERIFIED_NO_BETS` として仮想購入しない。モーター更新日が欠ける場は、場内の全掲載モーターが同一更新日で歴史データと一致するときのみ補完し、出典を記録する。
- 公開データに存在しないレース、開催延期、同日早い時間の節間成績などに欠けが出る場合はある。今節の前日までの確定走から推定し、同日分の過去走は厳格に除く。
- モーター世代の元データの一部は過去に収集した独自集計に依存。日付は現在の公開 `motor_stats` と比較し、不一致なら旧世代分を使わない。
- **自動精算**は毎日00:30 JSTのActionsに設定。結果連携のコードはローカル動作確認済みだが、翌日スケジュール実行の成功確認はまだ。払戻が未掲載ならpendingを維持する。
- 10月31日を起点に11月1日以降の差分を毎回再取得するため、何ヶ月も先まで高速運用するには集計基準日の定期更新が今後必要。3年データに新しい期間を加える集計は原則更新できるが、古い3年境界の自動除外も現時点では未実装。
- 推定期待回収率が高くても、過去の回収率が100%未満という検証結果があり、実際の収益性は確認できていない。

**完了扱いの根拠**：GitHub Actionsでの締切前モデル実行成功＋168入力確認＋120点オッズ照合＋仮想購入台帳への永続書き込みを実際に確認したこと。
